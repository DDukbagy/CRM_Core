# 관리자의 완료 되돌리기

- 상태: 완료
- 기간: 2026-11-25
- 브랜치 / PR: `crm` / #98
- 관련 작업: [지난 예약 자동 정리](booking-auto-cleanup.md), [동시 요청 문제](pass-deduct-concurrency.md), [예약 시 수강권 고정](booking-pass-pinning.md)

## 1. 문제

완료는 수강권을 차감하는데, 잘못 완료한 예약을 바로잡을 방법이 없었다. 강사가 다른 예약을 눌렀거나, 자동 정리가 실제로는 하지 않은 수업을 완료한 경우다.
지금은 수강권 횟수를 손으로 고치는 수밖에 없고, 그러면 예약은 완료로 남아 기록이 실제와 어긋난다.

관리자 웹에는 예약을 찾아볼 화면도, 관리자가 전체 예약을 조회하는 API 도 없었다.

## 2. 테스트 명세

"어떤 상황에서 → 무엇이 일어나야 한다" 형식.

- [ ] 1. 관리자가 완료된 예약을 되돌리면 → 200 을 반환하고 예약은 취소 상태가 되며 사유가 남는다. 수강권은 1회 복구되고, 그 시간은 다시 비어 있다
- [ ] 2. 그 완료로 수강권을 다 써서 '다 씀' 상태가 된 수강권이면 → 되돌린 뒤 수강권은 다시 사용 중 상태가 되고 남은 횟수가 1회 생긴다
- [ ] 3. 완료 상태가 아닌 예약(확정·노쇼·취소)을 되돌리려 하면 → 409 로 거부되고 예약과 수강권은 그대로다
- [ ] 4. 관리자가 아닌 사람(그 예약의 강사, 고객)이 되돌리려 하면 → 403 으로 거부되고 예약은 완료 그대로다
- [ ] 5. 같은 예약의 되돌리기 요청 두 개가 동시에 오면 → 하나만 200 이고 다른 하나는 409 다. 수강권은 1회만 복구된다
- [ ] 6. 완료된 예약 목록은 → 관리자에게만 보이고(강사는 403), 완료 상태인 예약만 강사·고객 이름과 함께 담긴다. 되돌린 예약은 목록에서 빠진다
- [ ] 7. 되돌린 예약은 수업일 + 3일이 지나 자동 정리가 돌아도 → 다시 완료되지 않고 수강권도 차감되지 않는다

## 3. 재현 (고치기 전)

- 테스트 이름 또는 실행한 명령: `make apitest ARGS="tests/test_booking_revert_complete.py"` (10개: 명세 3 은 3가지, 명세 4 는 2가지)
- 실행 환경: 로컬 Postgres 컨테이너
- 커밋: `4291476` + 테스트 파일

새 기능이라 10개 모두 실패한다. 되돌리기 주소와 목록 주소가 없다(404).

## 4. 원인

예약 상태는 완료에서 끝이었다. 완료에서 나가는 전환이 없고, 수강권 쪽에는 차감만 있고 돌려주는 동작이 없었다.

## 5. 선택지와 결정

**되돌린 예약을 어떤 상태로 두는가**

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 취소로 끝낸다 (완료 취소 + 1회 복구) | 자동 정리와 부딪히지 않는다. DB 변경이 없다. 규칙이 하나다 | 수업을 다시 잡으려면 새로 예약해야 한다 |
| B. 확정으로 되돌린다. 수업일이 3일 넘게 지난 예약은 되돌릴 수 없다 | 당일 실수는 그대로 다시 완료할 수 있다 | 자동 완료된 예약은 사실상 되돌릴 수 없다 |
| C. 관리자가 취소·확정 중에서 고른다 | 가장 유연하다 | 규칙과 화면이 늘어난다 |
| D. 확정으로 되돌리고 자동 완료에서 빼는 표시를 둔다 | 되돌린 예약이 그대로 남는다 | 예약 테이블에 칸이 하나 필요하다(마이그레이션) |

- 고른 것: A
- 이유: 수업일이 지난 확정 예약은 다음 날 자동 정리가 다시 완료·차감한다. 확정으로 되돌리면 관리자가 바로잡은 것이 하루 만에 원래대로 돌아간다. 되돌리기가 필요한 경우의 대부분은 "하지 않은 수업이 완료됨"이고, 그 예약의 올바른 끝 상태는 취소다

## 8. 남은 것

- 수강권이 고정되지 않은 예전 완료 예약은 되돌릴 수 없다(409). 어느 수강권에서 차감됐는지 기록이 없어서다
- 노쇼 되돌리기는 없다
- 목록은 그 예약이 자동 완료된 것인지 강사가 완료한 것인지 보여 주지 않는다. 구분은 로그(`booking.auto_completed`)에만 있다
- 목록의 "완료 처리한 날"은 예약의 마지막 수정 시각이다
- 그 예약에 연결된 레슨노트는 지우지 않는다. 취소된 예약에 노트가 남는다
