# 작업 기록 (worklog)

개선 작업 하나당 파일 하나를 남긴다. 목적은 세 가지다.

- 고치기 전 상태처럼 **나중에 다시 만들 수 없는 증거**를 그 자리에서 남긴다.
- 개발일지와 포트폴리오를 쓸 때 옮겨 적을 재료가 된다.
- 다음 세션(사람이든 Claude Code 든)이 이어받을 수 있다.

작업 순서와 배경은 `docs/improvement-plan.md` 에 있다.

## 규칙

1. 파일 이름: `YYYY-MM-DD-주제.md` (예: `2026-11-14-pass-deduct-concurrency.md`). 날짜는 작업을 시작한 날.
2. `_template.md` 를 복사해서 쓴다. 칸을 지우지 않는다. 해당 없으면 "없음"이라고 적는다.
3. **`테스트 명세` 칸은 사용자가 직접 쓴다.** Claude Code 는 이 칸을 채우거나 고치지 않는다. 비어 있으면 작업을 시작하기 전에 사용자에게 요청한다.
4. 터미널 출력은 요약하지 말고 **그대로** 붙인다. 길면 핵심 부분만 잘라 붙이고 잘랐다고 표시한다.
5. 측정하지 않은 수치는 적지 않는다. 수치에는 측정 조건을 붙인다.
6. 고치기 전 출력은 수정 커밋보다 **먼저** 기록한다. 수정한 뒤에는 다시 얻기 어렵다.
7. 토큰, 접속 주소, 키, 이메일·전화번호 같은 값은 붙여 넣지 않는다 (`CLAUDE.md` 4절). 출력에 섞여 있으면 가린다.
8. 작업 중에는 사실만 짧게 적는다. 문장을 다듬는 일은 개발일지로 옮길 때 한다.
9. 상태는 `진행 중` / `완료` / `보류` 중 하나로 맨 위에 적는다.

## 누가 무엇을 쓰는가

| 칸 | 쓰는 사람 |
|---|---|
| 테스트 명세 | 사용자 |
| 결정 (무엇을 골랐고 왜) | 사용자가 결정, Claude Code 가 선택지와 근거 정리 |
| 배운 것 | 사용자 |
| 문제, 재현, 원인, 수정, 결과, 남은 것 | Claude Code 가 작성, 사용자가 확인 |

## 끝난 뒤

- 완료된 기록은 티스토리 CRM 개발일지 한 회차의 재료다.
- 포트폴리오에는 `결과` 칸의 측정값과 한 줄 요약만 옮긴다.
